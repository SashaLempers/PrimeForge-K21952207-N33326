## Deterministic range selection

The preserved range target record was generated by PrimeForge's
`SHA256_WINDOW_V1` algorithm with these parameters:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/select_supported_discovery_target.ps1 `
  -Exponent 33326 `
  -CandidateCount 40001 `
  -DomainMin 10000001 `
  -DomainMax 99999999 `
  -Attempt 1 `
  -DateTag 2026-08-12 `
  -BaseCommit 279a7c76e1bcd1b0f96c60214f534b84c1b00282
```

The output selected odd `k=21909339..21989339`. The exact seed and its hash are
in `novelty_audit/range-target-and-queries.json`.

## Discovery controller

This is the path-redacted equivalent of the campaign invocation. Every numeric
argument is corroborated by `raw/campaign.json`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/run_prime_discovery.ps1 `
  -CampaignDirectory out/discovery/proth-n33326-k21909339-21989339 `
  -KStart 21909339 `
  -KStop 21989339 `
  -Exponent 33326 `
  -SieveBound 65521 `
  -BatchSize 100 `
  -Device 0
```

The campaign stopped at the first proven prime. Its checkpoint records
`PRIME_FOUND`, `completed_candidates=2161`, and `proven_prime_k=21952207`.

## Proth20 isolated reproduction

The preserved adapter was invoked with a one-line batch file containing
`21952207 33326`, device 0, and stop-on-prime behavior:

```powershell
proth20-batch.exe --device 0 --batch candidate.txt --stop-on-prime
```

The exact adapter may also accept a stop-file argument; it is not needed for a
single candidate. Expected output is preserved at
`proof/proth20-reproduction.stdout.log`. The binary is deliberately absent.
